01

The 30-second mental model

Before any file path makes sense, hold these five boxes in your head. Everything else is detail hanging off them.

Frontend

Two kinds of React

Server components run on the server, can read MongoDB directly, and send HTML. Client components ('use client') run in the browser and handle clicks, forms, modals, live search and SWR.

Rule of thumb: if it needs useState, useEffect, onClick or window, it is a client component.

Backend

No separate Express server

Next.js route handlers are the backend. Each route.ts exports GET, POST, PATCH or DELETE, wrapped by one shared route() function that handles DB, auth, rate limits, validation and errors.

Database

One source of truth

Every model lives in packages/db/src/models. Both the website and the agents import the same model, so a scraped listing and a page render agree on every field name.

Agents

A second runtime

apps/agents is a Node program, not a web server. It fetches hackathon sources, cleans them, dedupes and writes listings. The website imports it as a library for “Scrape now” and the cron route.

Shared

Contracts, not code

packages/shared holds types, city list, themes, source catalog and status rules. It has no database or network code, so it is safe to import anywhere.

AI

Optional, not required

packages/ai calls Claude when a key exists and falls back to regex/rule-based parsing when it does not. The site still works with zero AI keys.

✓

The one sentence to remember: “It is a pnpm monorepo where Next.js serves both the pages and the JSON API, all persistence goes through one shared Mongoose package, and a separate Node agent writes into the same database on a schedule.”

02

Monorepo anatomy

Why there are apps/ and packages/, how pnpm links them, and why the website can import TypeScript source without a build step.

The workspace file

pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'

That is the whole monorepo definition. pnpm treats every folder matching those globs as a workspace package. The root package.json is private and only holds scripts; it is not published.

The dependency graph

What workspace:* means

Inside apps/web/package.json you see:

"@hackathonfinder/db": "workspace:*",
"@hackathonfinder/ai": "workspace:*",
"@hackathonfinder/shared": "workspace:*",
"@hackathonfinder/agents": "workspace:*"

pnpm creates a symlink in node_modules/@hackathonfinder/db pointing at packages/db. There is no version negotiation and no publishing. Change a type in packages/shared and the next TypeScript check sees it everywhere instantly.

Why there is no build step for packages

Each package’s package.json points main and types at ./src/index.ts — raw TypeScript. Two consumers handle that differently:

  • Next.js compiles them because next.config.js lists them in transpilePackages.
  • The CLI runs them through tsx, which strips types on the fly.
◆

This is a deliberate trade: fewer build steps and instant cross-package refactors, at the cost of Next compiling more code. For a project this size it is the right trade. If packages grow huge, add a build step with tsup or tsc and point main at dist.

One .env, three readers

There is exactly one environment file at the repo root. It is parsed by three different entry points:

Next.js

apps/web/next.config.js reads ../../.env at config time and fills process.env only where a variable is not already set.

CLI / agents

packages/db/src/env.ts finds the repo root by walking up to pnpm-workspace.yaml, then loads .env.

Dev script

scripts/dev.mjs parses .env before spawning MongoDB and Next, so both children inherit the values.

!

Hosting wins. All three loaders only set a variable if process.env[key] === undefined. That is why Vercel’s dashboard values override the file, and why you should never commit a real .env.

Server component vs client component

Server (default)

No 'use client'

  • Can be async and await a database call.
  • Can import server-only modules.
  • Ships zero component JavaScript to the browser.
  • Cannot use useState, onClick, window or useEffect.

Example: app/(site)/hackathons/page.tsx calls getHackathons() directly.

Client

'use client' at the top

  • Runs in the browser after hydration.
  • Handles forms, filters, modals, live search, SWR.
  • Talks to the backend with apiFetch().
  • Cannot import server-only code (build error by design).

Example: components/hackathon/Explorer.tsx filters listings in the browser.

apps/web/src/lib/apiClient.ts — the only way the browser should call the API
export async function apiFetch<T>(path, init = {}) {
  const res = await fetch(path, {
    method: init.method ?? (init.body === undefined ? 'GET' : 'POST'),
    headers: init.body instanceof FormData ? undefined : { 'Content-Type': 'application/json' },
    body: init.body === undefined ? undefined : JSON.stringify(init.body),
    credentials: 'same-origin',   // send the session cookie
  });
  if (!res.ok) {
    const err = data?.error ?? {};
    throw new ApiClientError(res.status, err.code, err.message, err.fields);
  }
  return data;
}

Why this matters: every failure becomes a typed ApiClientError with status, code, message and optional fields. Forms can show per-field errors instead of a generic alert.

Providers: session + SWR in one place

// apps/web/src/components/Providers.tsx
<SessionProvider refetchOnWindowFocus={false}>
  <SWRConfig value={{ fetcher: swrFetcher, revalidateOnFocus: false,
                      shouldRetryOnError: false, dedupingInterval: 4000 }}>
    {children}
  </SWRConfig>
</SessionProvider>

This is mounted once in app/layout.tsx. Every client component can call useSession() and useSWR() without extra setup. refetchOnWindowFocus: false avoids a burst of requests when a student tabs back; dedupingInterval collapses duplicate requests made within 4 seconds.

The useMe hook — one source of truth for “who am I”

apps/web/src/lib/useMe.ts
const { status, update } = useSession();
const signedIn = status === 'authenticated';
const { data, mutate, isLoading } = useSWR(signedIn ? '/api/me' : null);
const me = signedIn ? data?.user ?? null : null;

const refresh = async () => {
  await mutate();   // re-fetch /api/me
  await update();   // refresh the NextAuth session (name, handle, photo)
};

Notice the null key: when signed out, SWR does not fetch at all. After a profile save, components call refresh() and both the API data and the session token update.

Backend core — the 300 lines every route depends on

There are 85 route files, but only one request pipeline. Learn server/api.ts and you have learned the backend. Every handler is a thin function that receives a validated context and returns data.

✓

The one-sentence version. A browser calls /api/… → Next.js runs the exported GET/POST → that function is a route(handler, options) wrapper → the wrapper connects to MongoDB, resolves the session, checks bans, applies a rate limit, runs your handler, converts ObjectIds/Dates to JSON, and maps every thrown error to { error: { code, message, fields } }.

The wrapper: route()

This is the highest-leverage file in the repository. Read it once and every endpoint becomes predictable.

apps/web/src/server/api.ts — condensed, behaviour-accurate
export function route<P>(handler, options = {}) {
  const auth = options.auth ?? 'optional';
  return async (req: NextRequest, context: { params: P }) => {
    try {
      if (!isDbConfigured()) throw new DbNotConfiguredError();
      await connectDb();                              // one cached connection per process
      const user = auth === 'none' ? null : await getSessionUser();
      if ((auth === 'required' || auth === 'admin') && !user) throw unauthorized();
      if (auth === 'admin' && user?.role !== 'admin') throw forbidden('This is for admins only.');
      // A JWT can outlive a ban or a deleted account: mutations re-read the account.
      if (user && !SAFE_METHODS.has(req.method)) {
        await assertActive(user.id, req.method === 'DELETE' && req.nextUrl.pathname === '/api/me');
      }
      const ip = clientIp(req);
      if (options.rate) {
        const key = `${options.rate.key ?? req.nextUrl.pathname}:${user?.id ?? ip}`;
        if (!rateLimit(key, options.rate.limit, options.rate.windowMs))
          throw new ApiError(429, 'rate_limited', 'You’re doing that too often…');
      }
      const result = await handler({ req, params: context?.params ?? {}, user, ip });
      if (result instanceof Response) return result;    // redirects, files, custom headers
      return NextResponse.json(toJson(result ?? { ok: true }));
    } catch (err) {
      return errorResponse(err);
    }
  };
}

  let raw;

Account state: assertActive()

A NextAuth JWT lasts 30 days. A ban or account deletion must take effect sooner than that, so every mutation re-reads two fields:

async function assertActive(userId: string, allowBanned = false) {
  if (!/^[a-f0-9]{24}$/i.test(userId)) throw unauthorized();
  const doc = await User.findById(userId).select('banned deletedAt').lean();
  if (!doc || doc.deletedAt) throw new ApiError(401, 'unauthorized', 'Please sign in again.');
  if (doc.banned && !allowBanned)
    throw new ApiError(403, 'account_banned', 'Your account is suspended…');
}

The single exception is DELETE /api/me: a banned student may still delete their own account. GET requests skip the check because reading is harmless; the admin area checks stillAdmin() separately on every call.

The admin layer: adminRoute()

Admin access is not just “the JWT says admin”. Roles can change after sign-in, and ADMIN_EMAILS can be edited. adminRoute() composes four checks:

  1. Admin in the session

    route(..., { auth: 'admin' }) rejects non-admins before the handler.

  2. stillAdmin() against MongoDB

    Reads role, email, emailVerified, banned, deletedAt. A demoted or banned admin loses access immediately. grantsAdmin() lets a verified ADMIN_EMAILS address count as admin.

  3. Same-origin for writes

    Anything except GET/HEAD/OPTIONS must come from the admin pages. Checks Sec-Fetch-Site and compares the Origin host with the request host.

  4. 90 writes per minute per admin

    A second, tighter limiter on top of any per-route limit, keyed admin-write:<userId>.

export function adminRoute<P>(handler, rate?) {
  return route<P>(async (ctx) => {
    if (!(await stillAdmin(ctx.user!))) throw forbidden('This is for admins only.');
    if (!SAFE_METHODS.has(ctx.req.method)) {
      if (!sameOrigin(ctx.req)) throw forbidden('That request didn’t come from the admin pages.');
      if (!rateLimit(`admin-write:${ctx.user!.id}`, 90, 60_000))
        throw new ApiError(429, 'rate_limited', 'Too many changes in a minute…');
    }
    return handler({ ...ctx, user: ctx.user! });
  }, { ...(rate ? { rate } : {}), auth: 'admin' });
}

Admin pages use requireAdminPage() instead. It redirects signed-out visitors to /admin/login?next=…, and signed-in non-admins to ?denied=1. safeAdminNext() only accepts paths that start with /admin, so the login page can't be used as an open redirect.

Rate limiting: simple on purpose

apps/web/src/server/rateLimit.ts
export function rateLimit(key: string, limit: number, windowMs: number): boolean {
  const now = Date.now();
  const bucket = buckets.get(key) ?? { hits: [] };
  bucket.hits = bucket.hits.filter((t) => now - t < windowMs);   // sliding window
  if (bucket.hits.length >= limit) { buckets.set(key, bucket); return false; }
  bucket.hits.push(now);
  buckets.set(key, bucket);
  if (buckets.size > 50_000) { /* drop idle buckets */ }
  return true;
}
  • Per user when signed in, per IP when signed out. Key format: routeKey:userId|ip.
  • Per process. On Vercel, each warm function instance has its own map. That is acceptable for abuse control, not for billing quotas. The code comment says: move to Redis if exact global limits matter.
  • Login has two limiters: 10 attempts per email and 30 per IP every 15 minutes.
  • Strictest routes: registration 5/hour, forgot password 5/hour, delete account 3/hour, thread post 5/10 min, reply 15/10 min.

// apps/web/src/server/cron.ts
export function assertCron(req: NextRequest): void {
  const secret = process.env.CRON_SECRET;
  if (!secret) {
    if (process.env.NODE_ENV === 'production') throw new ApiError(503, 'cron_not_configured', …);
    return;   // development: allow local testing
  }
  const given = req.headers.get('authorization')?.replace(/^Bearer\s+/i, '') ?? '';
  const a = Buffer.from(given), b = Buffer.from(secret);
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b))
    throw new ApiError(401, 'unauthorized', 'Wrong cron secret.');
}

Why timingSafeEqual: a normal string comparison returns faster on the first wrong byte, which leaks information about the secret. The length check is required because timingSafeEqual throws on different lengths.

server-only: the guardrail that prevents a leak

Every backend module starts with import 'server-only'. If a client component accidentally imports one, the build fails instead of shipping database code to the browser. This is why api.ts, auth.ts, admin.ts and all server modules can safely contain secrets and Mongo queries.

The connection: one socket pool, cached on globalThis

Why the cache lives on globalThis

Next.js reloads modules in development. A module-level variable would create a new pool on every edit until Atlas refuses connections. The cache is attached to the process global, so hot reload reuses the same connection. In production the process is reused across requests for the same reason.

packages/db/src/connect.ts

Why a failed connect is not cached

If mongoose.connect rejects, the code sets cache.promise = null and rethrows. The next request tries again instead of being permanently broken by one cold-start network blip.

The pipeline in one picture

One run, step by step

  1. A trigger asks for a scrape

    Manual “Scrape now”, Vercel Cron, the in-process scheduler, or the CLI. All four call launchScrape() or runScrapeNow().

    apps/agents/src/launch.ts
  2. The database grants a lock

    acquireRun() marks stale runs failed, then inserts an AgentRun with status: 'running'. A unique partial index refuses a second running scrape. A scheduled run also carries a slot, which is unique too.

    apps/agents/src/lock.ts
  3. Sources are synced and read

    syncSources() upserts a Source row per connector; disabled sources and connectors missing env vars are skipped. Each enabled connector returns RawCandidate[].

    apps/agents/src/sources.ts apps/agents/src/connectors/
  4. Each candidate is normalized

    City aliases, mode, fee, team size, themes, dates and organizer type are resolved from what the source said. The result is a Draft with every field optional until something proves it.

    apps/agents/src/pipeline/normalize.ts
  5. Obviously wrong events are dropped

    notHackathonReason() removes robotics races, esports, quizzes, fest passes and cultural events — but only when the title/tags clearly say so. When unsure, the event stays.

    apps/agents/src/pipeline/relevance.ts
  6. AI fills the gaps, rules fill the rest

    Connectors with extract: 'always' (posts, search leads) always call extractEvent(). Structured platforms call it only when key fields are missing. Without an API key, rule-based readers run instead.

    packages/ai/src/extract.ts packages/ai/src/rules.ts
  7. Place, image and QR enrichment

    Venues are geocoded through Nominatim (cached, one request/second), banners are mirrored to Cloudinary, and posters with “scan to register” are decoded with jsQR.

    apps/agents/src/enrich/
  8. Duplicates are merged, not duplicated

    The in-memory DedupeIndex checks source id, source URL, registration URL and title similarity. A match updates the existing listing and appends a source ref.

    apps/agents/src/pipeline/dedupe.ts
  9. Validation decides live vs review

    Missing key fields, broken links, suspicious prizes or payment links add flags. A flagged new listing is saved as pending; a clean one goes live.

    apps/agents/src/pipeline/validate.ts apps/agents/src/pipeline/checks.ts
  10. The run records itself

    Recorder batches counts, items and log lines to AgentRun at most every 1.5 s and writes a heartbeat. The admin dashboard polls the same row, so it can show live progress.

    apps/agents/src/run.ts

Dedupe — four rules, strongest first

1. Same source + same external id

The source’s own id (Unstop competition id, Devfolio slug) is authoritative. Same id means same event, no matter what the title says.

pipeline/dedupe.ts · 'source-id'

2. Same source URL

Normalized URL match catches the same page discovered twice, including tracking-parameter variants.

pipeline/dedupe.ts · 'source-url'

3. Same registration URL

Two platforms can list the same event and point at the same registration form. Titles must still be at least 50% similar, so a generic form link does not merge unrelated events.

pipeline/dedupe.ts · REG_URL_TITLE_THRESHOLD = 0.5

4. Similar title + close date + same place

Title similarity ≥ 0.85 after dropping case, years and punctuation, starts within 2 days, and same city (or both online). This is the fuzzy last resort.

pipeline/dedupe.ts · TITLE_THRESHOLD / START_WINDOW_MS

When a match is found, planMerge() keeps the more authoritative source’s values, fills gaps from the new one, appends the new sourceRef, and never overwrites a field a human verified.

Lock, slots and scheduling

Three doors, one lock

“Scrape now”, Vercel Cron and the in-process scheduler all call acquireRun(). The database, not the application, decides who wins:

  • unique partial index on AgentRun { agent } where status = 'running'
  • unique partial index on AgentRun { slot }

A duplicate-key error is translated into already-running or slot-taken, and the caller gets the existing run id.

Time budgets

RUN_BUDGET_MS = 40 min — stop taking new items; the rest waits for the next run. Vercel cron routes use a 240 s budget because the function must answer before the platform timeout.

STALE_RUN_MS = 30 min — a running row with no heartbeat is marked failed, so a crashed server cannot block scrapes forever.

Heartbeat is written at least once a minute by Recorder.

A slot id looks like 2026-10-25T02:00+05:30. India has no daylight saving, so the offset is always +05:30. needsCatchUp() lets a server that just started run a missed slot, but only if nothing has run since it and the next slot is more than an hour away.

Repair — fixing the past without re-scraping

pnpm agents:repair reads listings that have sourceRefs, loads their stored RawItem data, and re-applies the current rules: split one listing that wrongly merged two events, take down non-hackathon or in-person-abroad events, rewrite team size, themes, summary, tagline, prizes, and remove placeholder banners. Dates are not repaired because they need the source’s current timeline; the next scrape refreshes those.

✓

This is why RawItem exists. Keeping the raw source data means a rule change can be rolled out over existing listings without hitting every site again. It also makes debugging possible: you can see exactly what the connector saw.

Prompt cache

The system prompt is stable text with no dates or URLs, marked cache_control: ephemeral. High-volume runs reuse it instead of paying for the same instructions every time.

Low effort

Extraction is read-and-fill, not reasoning. effort: 'low' keeps runs fast and cheap; the schema still forces every field.

Vision

Posters can be sent by URL or base64. The model reads the image and the text together, which is how Instagram-style announcements become listings.

Errors & debugging — one envelope, one place to catch it

Every API failure looks the same to the client, no matter which route threw it. That consistency is created in one function, and it is the first thing to understand when something breaks.

The error envelope

every API error response
{
  "error": {
    "code": "bad_request",
    "message": "Some details need fixing.",
    "fields": {
      "email": "Enter a valid email address.",
      "password": "Use at least 8 characters."
    }
  }
}

fields is optional. It exists so forms can show the message under the right input instead of a generic toast.

Who consumes it

apiFetch() in the browser turns a non-2xx response into ApiClientError with status, code, message and fields. Components catch that type and render inline errors.

A network failure becomes code: 'network' with a friendly offline message — never a raw TypeError.

apps/web/src/lib/apiClient.ts

How route() catches everything

  1. Database check

    If MONGODB_URI is missing, throw DbNotConfiguredError before any handler code runs.

  2. Connect

    await connectDb(). A connection failure is caught by the same wrapper.

  3. Auth

    none skips session lookup; optional attaches a user or null; required throws 401; admin throws 401 then 403.

  4. Account state

    For any non-GET/HEAD/OPTIONS request, assertActive() checks the database: deleted → 401, banned → 403. Deleting your own account is the one allowed exception.

  5. Rate limit

    Key is path:userId or path:ip. Over the limit → 429 rate_limited.

  6. Handler

    Your function runs. It may return a plain object, a Response, or throw ApiError.

  7. Serialise

    Plain objects go through toJson() so ObjectIds and Dates become JSON-safe. undefined becomes { ok: true }.

  8. Map the error

    errorResponse() checks ApiError, then DbNotConfiguredError, then Mongo duplicate key 11000, then falls back to a logged 500.

!

Never leak internals. Unknown errors are logged on the server and returned as “Something went wrong on our side.” The stack trace, Mongo message and file paths stay in the server log. ApiError messages are written for humans and are safe to show.

Answer like an author — the questions people actually ask

Short answers first, then the detail you add if they nod. The goal is not to recite files; it is to show that every choice has a reason.

The 60-second pitch

“HackathonFinder.in is a pnpm monorepo with five packages. apps/web is a Next.js 14 App Router site and API. apps/agents is a separate Node discovery worker. packages/db owns 27 Mongoose models and the connection. packages/ai wraps Claude extraction with rule-based fallbacks. packages/shared holds the types, city/theme catalog and status rules used by everyone.

The request path is: page or client → API route → route() wrapper → server logic → Mongoose → mapper → JSON. Every route gets the same DB, auth, ban, rate-limit and error handling. The scrape path is: trigger → database lock → connectors → normalize → relevance → enrich → dedupe → validate → publish → live AgentRun log. The whole thing runs without AI; AI just makes messy sources usable.”

Architecture

Why a monorepo instead of one app?

The website and the scraper share the same models, types and rules, but have different runtimes and deploy targets. A monorepo lets them import the same Hackathon type and the same computeStatus() without publishing packages. pnpm links them with workspace:*, and Next transpiles the raw TypeScript packages.

Why does the frontend not call its own API for page data?

Server components can call the server function directly. An HTTP call to your own API adds a network hop, needs cookie forwarding, and duplicates serialization. The API exists for client interactions, mobile/extension clients and the admin dashboard; pages use the in-process function.

Why is packages/shared so small?

It holds only things that must agree across runtimes: types, the city/theme/source catalog, and status/distance rules. Business logic stays in the app that owns it. A shared package that knows about HTTP or Mongo would couple the agents to the web app.

What would you change first if this had to scale 100×?

Move rate limiting out of process memory to Redis, put the scrape queue on a real worker with a heartbeat lease, add read replicas or caching for listing pages, and split analytics writes into a batch pipeline. The route wrapper and the database lock are already the right seams for those changes.

Backend and API

Walk me through route().

It checks MONGODB_URI, connects, resolves the session according to the auth mode, enforces required/admin, rechecks the account for writes, applies the rate limit keyed by user or IP, runs the handler, converts the result to JSON, and maps any thrown error to { error: { code, message, fields? } }.

Why recheck the user row on writes if the JWT already has the role?

A JWT can outlive a ban, a deletion or a role change. The token says who signed in, not who they are now. Writes call assertActive(); admin routes call stillAdmin(). Reads can tolerate a slightly stale token; writes cannot.

Why is the rate limiter in memory?

It is deliberately simple and dependency-free for a single Node process. The trade-off is that limits are per instance and reset on deploy. The interface is one function, so moving to Redis is a contained change.

How do you prevent duplicate saves, votes and requests?

With database unique indexes, not application checks: SavedEvent (userId, hackathonSlug), Vote (userId, targetType, targetId), TeamRequest (post, fromUser), Cheer (user, win). A duplicate insert raises Mongo 11000, which errorResponse() turns into a 409.

How are cron routes secured?

assertCron() requires Authorization: Bearer <CRON_SECRET> and compares with crypto.timingSafeEqual. In production, a missing secret is a 503 rather than an open endpoint.

Auth and security

Explain the three ways to sign in.

Credentials: email + bcrypt password, rejected until the email is verified. Google and GitHub: OAuth, then the account is linked by verified email or by provider identity. All three end in the same User row and the same JWT session.

How does a password reset sign other devices out?

Reset sets a new hash and bumps passwordChangedAt. The JWT callback compares the token’s issue time with that value; older tokens are treated as signed out. It is a cheap global invalidation without a session table.

What makes someone an admin?

Either a database role of admin, or a verified email present in ADMIN_EMAILS — the allowlist grants admin at sign-in. The JWT is not enough: stillAdmin() rechecks the row, and admin writes also require same-origin.

Where are secrets kept?

Only in environment variables, documented by name in .env.example. .env and .env.vercel are gitignored. The client bundle has no NEXT_PUBLIC_* secrets; the health endpoint reports configured/not configured, never values.

How do you stop the scraper from being used for SSRF?

Every outbound URL goes through PublicUrlGuard, which resolves the host and refuses loopback, private, link-local, multicast and metadata addresses. It runs on every redirect hop and on robots.txt fetches too. The HTTP client also caps size, time and redirects.

Data and discovery

Why one Hackathon document with sourceRefs instead of one row per source?

Students care about the event, not the site that listed it. One document gives one slug, one save target, one set of stats and one review state. sourceRefs preserves provenance and lets dedupe answer “have we seen this source id before?” with an index.

Why compute status instead of storing it?

Status changes with time, not with a write. Storing it would require a job to flip rows and would be wrong between runs. computeStatus() derives it from three dates at read time, so a listing is never stale.

How does dedupe work?

Strongest first: same source + external id, same source URL, same registration URL with at least 50% title similarity, then fuzzy title ≥ 0.85 with a start date within two days and the same city (or both online). A match merges fields and appends a source ref instead of creating a row.

Why does the database own the scrape lock?

Because there can be several servers and three triggers. An in-process flag cannot coordinate them. A unique partial index on AgentRun where status = 'running' makes a second run impossible at the storage layer; a unique slot makes a scheduled run happen once. The app just translates the duplicate-key error.

What happens when one source fails?

The run continues. The source is recorded as failed with its error, the other sources publish normally, and the run ends partial. One broken site never blocks the whole scrape.

How do you respect robots.txt and avoid harming sites?

Honest bot user agent, robots.txt fetched and obeyed per host, one request at a time per host with a delay, Crawl-delay respected, backoff on 429/5xx, hard size/time limits, and no attempt to bypass CAPTCHAs or WAF challenges. Social platforms are read through search results or official APIs, not crawled.

AI

Why use AI at all?

Because a lot of Indian hackathon announcements are posters, Instagram captions and forwarded messages. Rules cannot reliably read “₹1.5 lakh prize, 14–15 Nov, Hinjewadi” from an image. Claude turns that into the same structured fields a platform API provides.

How do you stop the model inventing details?

The prompt forbids it, the output is a Zod schema with nullable fields, and the pipeline validates required fields and confidence before publishing. Low confidence or missing key fields go to pending, not live. The model never writes to Mongo directly.

What happens if the AI key is missing or the call fails?

isAiEnabled() returns false and extraction returns null; rule-based readers and templates run instead. Smart search falls back to the rule parser. A failed AI call never takes down a scrape or a search.

How do you control cost?

Only unstructured sources call the model; structured platforms use rules. The system prompt is cached, effort is low, text is capped at 120k characters, and the model is configurable with AI_MODEL. Smart search sends at most 300 characters.

Trade-offs and honesty

What is the weakest part of the architecture?

The in-memory rate limiter and the in-process scheduler both assume a small number of long-lived Node processes. On serverless, the scheduler does not run; Vercel Cron is the real trigger. Both are documented seams rather than hidden assumptions.

What is the hardest bug you would expect?

Dedupe false positives: two different college events with generic titles like “Hackfest 2026” on the same weekend in the same city. The 0.85 title threshold plus date/city guards reduce it, but the review queue and the admin merge/split tools are the real safety net.

If I gave you a week, what would you ship?

Move rate limits to Redis, add an idempotency key for submissions, add contract tests around the API envelope, and add a small end-to-end test for one full scrape fixture. Those four reduce the highest-risk operational surprises.
